## 当前投入方向

冻结 Discussion v1 功能扩张，继续维护可靠性、恢复与事实审查。日常任务先用
单 Agent；有独立证据或不同职责需要汇合时，再显式考虑 Discussion。这是使用
建议，现有 UI、路由和授权不变。暂不新增自动启动判断、Top-N 默认切换、
LLM router 或 embedding selector。

[QA-069](acceptance/qa-069-workspace-evidence-replay.md) 已固定三个历史问题，并
完成其中两组独立资料读取对照。取消超时题双方都是 2/4；Windows 题单 Agent
为 1/4，Discussion 为 0/4。两组累计分别使用 2 与 6 个 Run，耗时 50.987 与
91.645 秒。Windows Finalizer 错误删掉了上下文中已存在的 Reviewer 证据，
说明信息可达、成功读取和正确使用是三回事。逐项依据见
[独立于原始记录的审核](acceptance/evidence/qa-069-workspace-review-2026-09-06.json)。

已批准的累计 13 次调用用完，原始失败记录完整保留。另一个历史题的单 Agent
为 1/4，但 Discussion 答案被旧基准读取校验丢弃，不能形成完整配对；该校验
已修复。三组完整结果的验收仍未满足，不能据此写成阶段完成。已有结果继续
支持先维护可靠性、检查资料使用和最终交付，暂不增加路由复杂度。历史诊断
回放不能代表真实用户任务成功率或返工率；后续应使用独立的新任务验证。

## 已有事实

Finalizer 会收到明确的事实、约束和交付项检查要求：纠正有证据支持的错误、
保留正确内容，并明确未决问题。多人重复同一句话不会被提示词视为额外证据。
Reviewer、Task primary 和原参与顺序回退选出的 Finalizer 都适用该要求。
普通 Wave 中的 Reviewer 与其他参与者并行，不能读取尚未产生的同轮回答；
Finalizer 才能综合已接受的前序贡献。提示词不赋予模型审批或执行权限。

2026-09-06 的固定贡献回放中，新提示覆盖了 9/9 个预设评分项，旧提示为 7/9。
差异集中在一个重复边界错误场景；另外两个场景的固定评分相同。
新提示仍出现不当纠正和超出时间戳证据的推断，不能把评分项全部覆盖理解为答案完全正确。
该实验每组只有一次，使用同一请求模型和配置，由任务中的 Codex 直接审核，
没有独立人工盲评。

QA-068 已补齐剩余五组，连同 QA-067 的第一组，现在三道跨专业题与三道简单
对照题均有完整结果。两种方式同为 22/24，均有五题通过全部四项：单 Agent
用 6 个 Run、累计 101.317 秒；Discussion 用 18 个 Run、累计 226.319 秒。
三道跨专业题均为 4/4；耗时诊断题两者均为 2/4，把应为 30 秒的 Discussion
耗时答成 120 秒，Finalizer 没有纠正贡献者的共同错误。

表中只比较完成的配对，另保留两次失败的 Discussion，共增加 6 个 Run 和
635.073 秒等待。QA-068 定位并修复了评估元数据不合法导致答案未送达的缺陷，
没有把失败改写成成功。四份修复后的最终答案仍按既有降级行为保留了不合法
元数据的原文；它不构成结构化审核通过，评分也不代表输出格式完全理想。

这些结果来自两个调用批次中的完整配对、一个请求模型和非盲的任务内审核，
其中前一个批次曾提前失败，并非独立重复实验。此样本没有显示 Discussion
质量收益；约 2.23 倍的累计耗时是本地
观察，不是性能保证，也不能据此断言 Discussion 对所有任务都无价值。

## 如何选择

以下是人工选择建议，不是自动规则，也不是已验证的任务分类器。

| 当前任务情况 | 建议起点 | 理由与证据边界 |
| --- | --- | --- |
| 给定事实已足够，输出是明确计算、局部修复或状态解释 | 先用单 Agent，并列清验收项 | 多个重复回答不等于新增证据；QA-065 中没有观察到额外质量覆盖 |
| 跨多个专业，但一个 Agent 已拿到完整资料 | 先检查单 Agent 的遗漏和未决点 | 完整对照的三道跨专业题均没有显示 Discussion 的评分增益；跨专业标签本身不是启动理由 |
| 需要不同成员提供独立事实、不同本地工作区信息或不同职责的意见 | 可考虑显式启动 Discussion | QA-069 已测试小规模历史信息差异，尚未观察到质量收益；需要独立真实任务继续验证 |
| 现有回答缺少事实或可验证依据 | 先补齐资料，明确未知项 | 增加同样缺少资料的参与者不能被当作事实验证 |
| 工作流程本身需要多方意见记录 | 可使用 Discussion 收集意见 | 流程价值与答案质量提升应分别验收；最终接受和执行仍由现有授权流程控制 |

启动前，应说明每个参与者将补充什么信息或审查什么问题，给出最终交付项、
参与规模和轮次/时限，并指定哪些不确定项必须保留。结束后检查最终答案是否
纠正了错误、是否遗漏要求、是否错误修改了原本正确的结论，以及增加了多少
实际 Run 和等待时间。Reviewer 自报通过不能替代验收。

## 为什么暂时保留 Broad fallback

当前聚焦匹配成功时已有确定性的成员缩减；首次、无聚焦问题或无匹配时保留
所有可用参与者。QA-067 的离线检查表明，按原顺序取两个并保留 Reviewer，
可能因成员排序漏掉题目所需的 Security 视角；换一个排序又可能保留它。

这是构造场景中的成员覆盖差异，没有调用模型，也没有证明最终答案变差。
因此继续保留生产策略。下一次真正的 Broad/Top-N 对照应固定无匹配任务、
可用成员、Reviewer 要求、模型与评分标准，并同时检查遗漏、正确内容保留、
实际 Run 和耗时；只看到参与人数下降不足以改变默认策略。

## 下一阶段的证据条件

六组固定对照已经补齐；下一阶段需要更有代表性的任务或独立重复实验，尤其是
不同成员确实掌握不同事实的场景。此前失败和原记录中的未执行项继续保留，
不能通过替换旧记录制造完整成功。新实验仍应有明确上限，同时保留简单对照，
给单 Agent 相同资料及审查要求；修改题目措辞或评分标准需要新版本，不能
与旧结果直接合并。

只有在代表性任务中反复观察到可解释的收益后，才有依据考虑自动启动建议或
更复杂的路由算法。本轮没有实现自动启动判断、LLM router 或 embedding selector。
[ADR-0043](adr/0043-remove-discussion-token-cost-accounting.md) 的 token 与费用
统计移除决定继续有效；产品保留 Run、轮次、槽位和耗时等现有统计。

# ConveneWire v0.5.3

This update brings the Node-first desktop to macOS and Windows, with a local
workspace and an integrated Agent console. Existing remote Bridge profiles remain
available. Manual upgrades preserve local identity, configuration and work records.

## Changes

- Work locally without deploying a Central server first. The desktop includes
  the native Node host, Hub, Web UI and matching runtime dependencies.
- Connect Nodes through reviewed Peer invitations and HTTPS network settings.
  Direct LAN use has owner-confirmed macOS/Windows evidence. Relay/Tunnel setup
  is available; public-network acceptance remains deferred.
- Configure local Agents in the same desktop window, with model reporting and
  consistent toolbar controls.
- On macOS, experimentally hand an existing Codex desktop conversation to a
  Room Task while retaining its original conversation ID, history, workspace
  and tools. Explicit cooperative startup and local disclosure consent are
  required. Interrupted or uncertain ownership pauses for review; returning
  control does not create a replacement conversation.
- Correct the Windows portable ZIP layout so native Hub dependencies retain
  valid paths after extraction.

## Platforms And Upgrade

Windows users should download `convenewire-bridge-desktop_0.5.3_windows_amd64_setup.exe`.
The portable ZIP is also available. macOS uses the Apple-silicon desktop ZIP.
Windows Codex desktop conversation takeover is not supported in this release.
Packages remain unsigned and unnotarized; Windows requires WebView2.

Quit ConveneWire before replacing or upgrading it. Keep a stopped Node snapshot
and its matching old application together. The current database includes migration
`0105`; rollback requires restoring a compatible snapshot with old binaries.
Never open an upgraded database with an older version. Central deployments should
use matching Server, Web and Bridge versions and follow their backup procedure.

## Evidence

[QA-094](../acceptance/qa-094-codex-desktop-handoff.md) records isolated native
same-conversation continuation, consent, restart and return, using a local fake
provider. It does not claim validation of the owner's private conversations or
Windows conversation takeover. [QA-092](../acceptance/qa-092-ab-native-desktop.md)
records the separate physical LAN evidence.

The [release record](../acceptance/qa-095-v0.5.3.md) tracks exact-source CI,
native packaging, Windows upgrade checks, download verification and the owner's
local macOS upgrade. Publication does not claim public Relay or live-model
acceptance.

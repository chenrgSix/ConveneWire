# ConveneWire v0.5.1

This release brings owner-authorized private evidence into production
Discussion and adds native Windows protection for private Bridge output. It is
a stable update for trusted small Teams, published as Latest on 2026-09-07.

## Private Evidence And Discussion

- A private Agent retains its raw output on its own Bridge. Its owner reviews
  and approves the exact content and scope before publication as a Result.
- Central authenticates the owner session and Device credential, checks the
  current grant at publication commit, and rejects changed or revoked releases.
- An approved Result automatically becomes the original Discussion turn's
  evidence. Finalizer inputs retain source identity, version, provenance and
  unavailable contributions; late publications cannot rewrite frozen inputs.
- Windows creates private files with a protected native ACL before writing
  content, rejects unsafe paths and permissions, and fails closed when private
  storage cannot be established. This is file protection, not a Runtime sandbox.

## Task And Result Usability

Task criteria, Result claims and source references can be inspected together.
Reviewed reports can be exported, Task definitions copied into independent
drafts, and common Plan fields edited with exact-revision recovery. Work filters,
search and attention views make pending actions easier to find. Discussion
selection reasons remain visible without turning usage into token/cost estimates.

## Downloads And Upgrade

The unchanged 12-asset distribution contains Linux amd64/arm64 CLI archives,
Apple-silicon macOS and Windows amd64 Desktop archives with advanced CLI helpers,
a Windows installer, one Central source archive and checksum pin, the outer
checksum manifest and four license/policy files. Central builds through Docker
Compose on the target. Packages remain unsigned and unnotarized; Windows Desktop
requires WebView2, and updates remain manual.

Use matching Central, Web and Bridge versions. Protocol remains `1.0`; the
database advances from v0.5.0's migration `0086` through `0088`. Back up and
verify Central before upgrading; retain v0.5.0 packages and required operator
secrets. Rollback requires restoring that backup with matching old binaries into
an isolated target. Never open a migrated database with old binaries. Publication
does not upgrade an existing installation or establish general-production,
independent-human-owner or live-model admission.

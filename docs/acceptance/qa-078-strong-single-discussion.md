# QA-078：强 Single Agent 与 Discussion 对照设计

这轮只问：**同样是 GPT-5.5，看得到同样的资料，分工后汇总是否比一个 Agent
自己完成更容易交付正确、完整的结果？它增加了多少会话和等待时间？**

按 [ADR-0052](../adr/0052-compare-strong-single-and-discussion.md) 执行研究边界。
本文确定比较协议和选题。Owner 随后授权“制作并冻结题包、参考答案和评分规则到
实验完成做完”，本轮最多十二次会话的授权写入题包；不需要再次确认。
交付状态只在 [TASKS](../TASKS.md)，准备证据与最终实验结果分别保留。

## 新任务：多租户异步导出服务的上线审查

准备一份新的合成工程资料包：用户提交导出请求，服务记录任务，后台 worker
生成文件，用户随后下载。评审需要跨越 API、数据库、权限、worker、故障恢复
和测试记录，不能只读一个函数得出结论。任务要求交付上线判断、可复现的问题、
必要修复与回归方案，并保留资料不足以确定的事项。

| 资料域 | 冻结内容 | 在 D 中负责的成员 |
| --- | --- | --- |
| API / storage | 请求处理、幂等键、事务、表约束和状态写入的相关完整实现 | Contributor 1 |
| Security / authorization | 租户身份来源、对象授权、下载授权及撤销规则 | Contributor 1 |
| Operations / recovery | worker、重投、租约、取消、崩溃恢复的相关实现与运行记录 | Contributor 2 |
| Test evidence | 测试代码、运行结果、环境与未执行范围 | Contributor 2 |

四域都进入 S 和 D Finalizer 的完整来源索引与读取授权。两个 Contributor 看见
同一任务及全部验收要求，但只读取分配给自己的域；同轮不看对方输出。跨域缺口
应报告为缺口，不猜测另一域实现。来源名称与目录不标出“正确答案”或“故障点”。

这些材料由实验作者新建，不冒充用户事故或真实生产日志。需要包含可工作的正确
路径、跨文件才能确认的问题，以及真实限定的资料缺口。缺陷和正确事实在模型
调用前固定；不能先测 S，发现它全对就加难题，也不能挑只有 D 做对的题发布。
任何模拟运行记录都标明模拟；真正执行的离线测试保留可核对的命令及结果。

该题是限定资料下的工程审查，不是现场编程修复。工具只允许固定来源读取及其
发现机制，两臂都不能运行 shell 或修改系统。这里的“Strong”指指定强模型在
该审查环境中的基线，不等于它在完整 IDE、多轮交互或任意工具下的最佳能力。

## 两臂只差分工产生的贡献

| 条件 | S：Single | D：Discussion |
| --- | --- | --- |
| 请求模型 / effort | GPT-5.5 / low | 三个会话均为 GPT-5.5 / low |
| 原始资料 | 全部四域 | 团队覆盖全部四域；Finalizer 也能直接读全部 |
| Task、Criteria、来源版本 | 相同 | 相同 |
| 最终作答的基础指令、Evidence Use、工具 | 相同 | 相同 |
| 最终作答的时间和输出限制 | 相同 | 相同 |
| 前置成员贡献 | 无 | 两份当次真实生成的独立贡献 |
| 单次试验会话数 | 1 | 2 个 Contributor + 1 个 Finalizer |

公共 Evidence Use 规则要求最终作答前完整读取四域来源、依据资料核对结论、
覆盖公开任务要求并保留未知事项。不给两臂任何私有评分答案，也不新增 claim
disposition、criterion closure、Reviewer 身份提示或额外自评表。

S 可以在同一会话内自行检查、修改答案；不能故意禁止它自检来削弱基线。
D Finalizer 使用一个全新会话，避免继承某个 Contributor 的隐藏上下文。
除中立的贡献说明和两份贡献外，其最终作答输入应与 S 逐项一致。

D 的两份贡献**每次重新生成**，不得复用旧题笔记、人工答案或上一重复的贡献。
冻结的是生成指令、域分配、现有 Result/source 表达、传递顺序和字节限制。
留存完整成员输出、实际传入 Finalizer 的字节、哈希及遗漏信息；不给研究人员
删错、补事实或另写摘要的机会。超限按事先定义的传递失败记录，不能静默截断。

这是隔离实验适配器中的固定两成员分工加汇总流程，复用现有 Result/来源语义
和 reader，不新增平行 Contribution 存储。生产 Discussion 的调度、存储、
完成策略、participant selection 不改。适配器与生产指令及会话方式的差异必须
列入冻结清单；不把该流程的结果称作生产 Discussion 端到端验收。

## 次数、顺序与失败

| 配对重复 | 先运行 | 后运行 |
| --- | --- | --- |
| 1 | S1 | D1 |
| 2 | D2 | S2 |
| 3 | S3 | D3 |

最多 12 次模型会话，形成 6 个计划中的最终交付：S 共 3 次，D 共 9 次。
每个 D 内两个 Contributor 并发启动，二者终止后才启动 Finalizer；贡献按
固定成员顺序传入，不能按完成快慢排序。S 与 D 的试验互不并发，也不共享会话。
工具往返可在同一会话内发生；“12 次”不是 HTTP 请求数。

每会话最多五分钟，读取最多 8 次、每次返回最多 8,192 UTF-8 字节；四份完整
来源必须各自能在一次返回内装下。所有角色终稿上限均为 32,768 UTF-8 字节。
冻结前以完整参考交付证明限制足够，不设置额外的短字数限制。最终答案采用普通
可读文本；格式表现单列，不以 XML 标签或某个字面词作为业务正确性条件。

每个会话启动前占用唯一名额。无重试、补跑、模型替代、追加讨论或模型裁判。
成员失败时不补造贡献；Finalizer 仍占原定名额，收到实际可用贡献与明确的失败
状态，并保留完整来源访问。D 流程有效性与最终答案质量分别记录。若调度器本身
中断，保存已消耗及未启动名额，关闭本计划；不能用成功样本替换失败样本。

完整执行计划要绑定资料与代码冻结哈希、当前 CLI/工具配置和 Owner 对本轮
最多十二次会话的授权。本文不是复用 QA-077 六次许可的理由。不得为“先看看题
难不难”偷偷增加真实模型试跑。

## 调用前先证明题目和评分站得住

所有要求先写入模型可见的 canonical Task Criteria。以下是本题的验收范围，
不是已经写好的隐藏标准答案；各项的精确行为、资料引用和测试输入必须随题包
一起完成，出现规范歧义时在模型调用前解决。

| 验收范围 | 实际要求 | Critical |
| --- | --- | --- |
| API 与数据一致性 | 对请求、幂等与持久化提出证据支持的判断；问题给出触发输入和可观察后果 | 是 |
| 授权与租户隔离 | 检查创建、处理、下载各阶段的对象和租户边界，不把身份认证等同于对象授权 | 是 |
| 重试与故障恢复 | 检查提交后响应丢失、worker 崩溃与重投的行为，区分已知状态和未知副作用 | 是 |
| 并发、取消与旧 worker | 根据实现判断竞争结果，提出满足已知约束的修复，不凭空承诺 exactly-once | 是 |
| 回归方案 | 每个确认问题都给出具体前置条件、操作和可观察期望；保护已有正确路径 | 是 |
| 上线判断与修复顺序 | 明确是否建议上线、依据、阻断项及验证顺序；提出修复不等于声称已经修复 | 是 |
| 正确信息保留 | 保留冻结的必要正确事实，避免为修复一个问题破坏已有正确约束 | 是 |
| 不确定性与证据范围 | 保留冻结的必要未知项，说明需要什么资料；区分已执行测试与建议测试 | 是 |

完整交付要求所有 required criteria 通过。本轮这些范围都关系可执行的工程
判断，因此都列为 critical；若最终题包另有纯展示要求，单独标为非关键项，
不得事后为了区分两臂才调整 critical 集合。两个指标相同也如实报告。

参考交付必须能在同样输出限制内覆盖全部要求。能够形式化的行为用离线正反例
校验；等价措辞和等价安全处理用语义评分。评分器要接受等价正确答案，也要拒绝
具体错误、漏掉要求和把模拟测试说成实测的答案。不要用与实现完全同构的测试
来证明题目正确，不要求模型猜测未给出的环境或内部约定。

先固定必要事实与未知项的独立列表，每项绑定来源和适用条件；不要用“整个
criterion 通过”代替“这个事实是否保留”。不能以资料中存在某句话，就要求
最终答案逐字复述它。

## 评分、取证与解释

最终答案导出后去掉 arm、成员输出和耗时，先保存逐项语义初评，再打开贡献和
运行记录分析机制。表述可能暴露 arm，实验作者也知道参考答案，因此只能称作
遮蔽标签的初评，不能称为独立人类盲评。没有额外 LLM grader 调用。

每项初评保存结论、答案原句和原始证据，分别标记实际错误、交付缺失与措辞
歧义。规范无法裁定的歧义记为 disputed，保留原评并追加复核；不能一律算通过，
也不能只凭歧义宣布一臂失败。完整通过、明确失败、争议待定、运行未交付分别
给出数量，以三次计划试验为分母。解释结论须检查争议采用不同合理解释时是否
仍成立。

| 指标 | 记录方法 |
| --- | --- |
| Full deliverable pass | 全部公开 required criteria 的语义验收；歧义不隐藏在二元总数里 |
| Critical criteria pass | 固定关键项全部通过；不给“平均做对几项”的替代分 |
| Unsupported additions | 逐条列新增无证据事实及影响；合理建议和有条件推断单独辨别 |
| Correct fact retention | 两臂均对照同一必要事实列表；D 另查正确成员事实是否进入并保留在最终答案 |
| Unresolved preservation | 逐项保留必要未知及所需资料，合理保留未知不等于未完成审查 |
| Evidence returns | 每角色应读来源、实际完整成功返回、失败和拒绝分别记 |
| Runs / failures | 实际启动数、完成数、成员失败和最终作答失败；不能只看成功子集 |
| Wall time | 从该臂首会话启动到终止的实际时长，包含 barrier 和传递；另列各会话耗时之和 |

manipulation 检查必须证明 S 与 D Finalizer 的 catalog、grant、四域完整返回
及公共输入一致；成员在冻结的域内独立生成，全部可用贡献完整进入当次 Finalizer。
回执只证明实际返回字节；不称作“模型已经理解”。成员成功但没有按规则读取是
协议未遵循，不能硬归因为综合能力。工具、传递或读取失败保留在结果里；可以
评价已有答案，但不能据此宣称一次有效质量对照。来源读取由 evidence identity、
版本、范围及当前 Run/Task/Room/authority 绑定，沿用已验证的回执字段。

预先固定解释如下：

- D 完整及关键通过 3/3、S 完整通过至多 1/3，且执行有效、D 无新增无依据事实、
  必要事实与未知均保留、评分歧义不改变结论：出现该题上的候选信号，才值得再用
  另一项独立任务验证；不能宣布 Discussion 产品质量提升。
- 两臂都完整通过：没有观察到质量增益，直接比较整个团队的会话数和等待时间。
- 两臂都未完整通过：没有证明可交付性改善；逐项错误仅用于诊断，不包装成胜利。
- S 持平或更好：本题未见 Discussion 的额外质量价值，保留实际信息损失及开销。
- 其他混合结果或处理失败：证据不足，按原计划报告，不加跑到想要的结果出现。

这是同一道新题的三次重复，不是三种独立任务。D 花了更多会话；即使胜出，也
不能分辨额外计算和分工组织各自贡献，更不能宣称同等资源下优于强 Single。
继续遵守 ADR-0043，不新增 token/费用核算。若今后需要回答等资源问题，应另立
新任务比较允许同等计算的单 Agent；本轮不偷偷加第三臂。

权限分离、独立证据和多人治理仍是 Discussion 的合理使用场景。但本题给两臂
授权同一资料全集，不能同时把它当作真实权限隔离价值的证明。

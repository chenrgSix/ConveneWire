# WEB-095 — 当前 UI 体验与工作台整改

本次从当前源码重新阅读并构建，在隔离的产品体验环境中操作工作台、房间、
任务新建、任务详情、设置和新增智能体入口。判断来自本轮页面与代码，
没有沿用历史验收结论。使用合成团队和数据，没有访问安装版用户资料或调用外部模型。

## 发现与设计依据

1280 × 720 的首页把大段宣传文案、搜索和六个下拉筛选放在任务前面。
第一张任务卡从约 y=446 才开始，每张卡重复呈现 `0/0`、运行次数和“用量未知”。
页面应该先帮助用户回答“有什么任务、下一步做什么、由谁处理”。

分组“需要我处理”实际上只判断下一步执行者类型为 member，团队范围也会包含他人任务。
任务按钮的可访问名称只有编号，屏幕阅读器无法直接读出任务标题。

同轮发现的房间归属、窄屏导航和内部状态文案分别由
WEB-096、WEB-097 和 WEB-098 记录；交付状态仅在 TASKS.md 维护。

## 整改与本轮验证

首页保留任务、范围、搜索、常用关注筛选及新建操作。高级筛选按需展开，
折叠后仍显示数量、已选条件和清除入口；从链接恢复的条件同样可见。
卡片突出任务标题、负责人和下一步执行人，保留实际验收进度，去掉空的诊断块。
“待处理”不再暗示全由当前用户负责；可访问名称包含任务标题。
无任务与无匹配结果使用不同说明。

同视口第一张卡现在从约 y=273 开始，首屏完整展示两排、四张任务卡。
实际浏览器验证了展开筛选、选择草稿、折叠后保留条件与清除筛选，
并检查浅色主题。相关七个测试文件 55/55 通过。全部整改完成后的 Web 门禁为
398/398 通过、0 跳过；TypeScript、生产构建、579 份文档 lint、
278 个本地链接目标及空白检查通过。构建仍有现存的大 chunk 提示。

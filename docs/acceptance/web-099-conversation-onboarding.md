# WEB-099 — 对话优先的房间引导

原空房间同时展示三种接入方式和底部配置提示；已有 Agent 但未就绪时，
仍要求重新配置。现在空对话只展示一处简短引导，接入选项按需展开。
状态区分加载中、房间无 Agent、任务未指派、暂未就绪、演示和真实就绪。
已有 Team Agent 时优先进入房间成员设置；离线提示进入 Agent 状态页。
普通成员聊天始终可用。真实回复判断限定在当前任务，不再由其他任务的消息抑制引导。

同时修复提问按钮的实际行为：原按钮调用的提及选择只适用于已输入 `@` 的搜索，
空输入框点击无效。新的主动选择入口追加提及，保留草稿、避免重复，并遵守当前
房间、任务、会话和最多五个目标的约束；不会自动发送。

六项引导/App/native 测试、20 项提及保留测试、22 项相关键盘/持久化/接入选择测试
通过。覆盖普通消息零 Run、加载与就绪分支、引导去重、重复点击、已有草稿、
焦点、同名目标、已失效上下文和同批目标上限。TypeScript 和生产构建通过。

本地隔离浏览器中实际创建 Team、房间和任务，核对普通聊天、演示目标追加、
已配置但离线的提示、任务未指派提示，以及已有 Agent 加入房间入口。
点击两次后草稿仍为原文加一个提及，焦点留在输入框；发送普通消息后，
空态消失且仅保留一处紧凑提示。桌面浅色与 390px 深色均已检查。

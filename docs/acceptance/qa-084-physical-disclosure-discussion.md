This is an unexecuted physical acceptance procedure. Its delivery state exists only

## Required owner decisions

Identify two actual owners, each one's POSIX device and private workspace, the
target Central installation and exact installed build. Each owner authorizes their
own installation/configuration and selects a non-sensitive fixed source snapshot
plus exact text permitted to enter the shared Room. No credential or private
source needs to be transferred to the other owner or Central.

Use a shared-output Finalizer on an authorized device. If a real model is used,
freeze its model/effort, tools, data handling and invocation budget beforehand.
Do not reuse historical benchmark permission. A deterministic Runtime can instead
verify transport; its outcome must be labeled accordingly. Windows private mode
is unsupported until its separate ACL implementation and native acceptance.

## Exercise

1. Record Central/Bridge source versions and the two independently administered

2. Configure one private Agent per owner. Assign both and a shared-output Finalizer

3. Start Discussion. On each device, verify the private candidate exists only in
   its local protected storage. Central must show a completed Run and a contribution
   waiting for owner release, without raw candidate output.
4. Each owner uses the documented CLI prepare workflow, reviews the exact text,
   approves its metadata in their own full Web session and publishes with their
   paired Bridge. Verify owner, destination, source revision and released digest.
5. Finish the Discussion and retain the canonical turn Result references, actual
   Finalizer input identity/digest and shared reply. Verify that both authorized
   disclosures arrive and omitted facts stay unresolved. Human Result acceptance
   remains a separate action.
6. In a separately scoped repeat, withhold or revoke one unpublished release.
   Finish or reach the Wave deadline. Verify bounded uncertainty, no unauthorized
   source retrieval and no extra private Runtime invocation while waiting.
7. Exercise an offline/reconnected consumer, publication response loss and Central
   restart using only the prepared test installation. Confirm exact retry and one
   admitted contribution; late Results cannot rewrite an existing final input.
8. Have each owner approve cleanup of their own test files/configuration. Retain
   sanitized receipts and outcome records, without private paths, bearer tokens,
   raw snapshots or unapproved candidate text.

inclusion and semantic deliverable acceptance separately. One successful run
proves that specific physical workflow, not general distributed reliability,
arbitrary free-text safety or superiority over a strong Single Agent.

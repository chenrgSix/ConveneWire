In [windows-availability](/private/tmp/convene-wire-test-run-D4tZX6/tmp/conveneewire-discussion-bench-MsVBUk/workspace/Solver/bridge/internal/console/server.go) `executableAvailable` requires a regular file with Unix execute bits (`0o111`). That is appropriate for Unix binaries, but it will reject Windows launchers and npm shims such as `codex.cmd` before the Runtime probe can run.

Minimal consistent policy: keep discovery, but make validation platform-native.
- Unix: preserve the current `executableAvailable` check.
- Windows: treat launcher files as valid if they are regular files with a recognized launcher extension (`.exe`, `.cmd`, `.bat`) or otherwise accepted by Windows command resolution.
- Do not relax Runtime permissions; only change discovery/availability checks.

Checks to add:
- Portable check: discovery still resolves absolute paths and does not execute shells or source profiles. `windows-discovery` already shows the intended no-shell behavior for nvm scanning.
- Native Windows check: a discovered `codex.cmd` and native launcher path should be accepted by availability logic.
- Unix regression check: `.cmd` remains non-authoritative on Unix, and execute-bit gating still works.

In `windows-console-preflight`, the console also marks an agent `ExecutableReady` only through `executableAvailable(executablePath)` before any Runtime probe, so the agent can be reported unavailable before runtime validation. Evidence: [`windows-enrollment`](#) and [`windows-console-preflight`](#).

Minimal consistent policy:
- Keep discovery portable: continue using path resolution / lookup without executing anything.
- Make validation platform-aware:
  - Unix: require a regular file with an execute bit.
  - Windows: accept native launchers and shims that are launchable by the OS, including `.exe`, `.cmd`, `.bat`, and PATHEXT-resolved entries; do not require Unix permission bits.
- Keep Runtime permissions unchanged.

Checks to separate:
- Portable discovery check: “can the path be resolved?”
- Native-platform launchability check: “is this path a valid executable for the current OS?”

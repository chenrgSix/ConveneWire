# WEB-096 — 明确新任务归属和对话状态

本轮审阅发现工作台的房间筛选独立于当前对话房间，旧“新建任务”总是向后者提交。
从 A 房间进入工作台、筛选 B 后，用户可能在 A 中创建任务，弹窗仅以小字提示位置。

新建弹窗现在提供明确的“所属房间”，工作台入口默认跟随单房间筛选，
对话入口默认当前房间。候选智能体按所选房间加载；切换房间清空旧指派，
晚到响应不能恢复另一房间的候选。加载失败有重试入口；错误留在当前弹窗。
提交和成功后的导航使用同一目标房间。

对话选择器将默认 `Room work` 展示为“默认对话”，任务状态使用本地化标签，
不再直接呈现 `working/open`。新建说明改为对话、进度、成果的用户语言。
这些只是展示和客户端选择，不修改后端存储名称或协议。

实际隔离浏览器完成 A 对话 → 工作台筛选 B → 新建“UI 归属验证”，
弹窗选择和任务详情均显示 B。测试使用真实临时 Server 检查准确 POST 目标、
工作台及对话两种入口、切房间后的指派和成功导航；另覆盖旧请求晚到、加载失败重试、
默认对话与六种状态展示。另验证旧 Team 延迟创建不能清除新 Team 请求的忙碌状态。
五个定向测试文件共 19 项通过，TypeScript 通过。

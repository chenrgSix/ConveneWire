# ADR-0047: Screen Finalizer evidence access and use

- Date: 2026-09-06
- Status: Accepted for a bounded experiment
- Owner: Discussion experiment tooling; no production capability change

## Decision

The Owner authorizes one historical diagnostic case, three treatments and
three interleaved repetitions, with at most nine fresh Finalizer invocations.
Q1 asks whether source access helps correct the target error. Q2 asks whether
an explicit evidence-use rule helps beyond access. This is mechanism screening.

Select QA-069's Windows launcher diagnosis before inspecting the retained
contribution text for this experiment. Include **all four original sources**,
using their original fixed excerpts and revisions. This selection rule is
independent of contributor correctness. C must check every source in that
manifest; it receives no expected answer or preferred contributor. All arms
see the same identities, neutral criteria, original contributions, Task and
base instruction generated by current production code. Historical scoring
rubrics and answers remain outside model input and tool-accessible data.

Freeze order A/B/C, B/C/A, C/A/B. A uses current baseline instructions with no
new source reader. B adds only the fixed source reader. C has B's reader and
adds only the frozen all-source checking requirement. Use the same requested
model, reasoning effort, output bound, runtime configuration and timeout.
Reserve each invocation before provider startup; failures consume slots and
are retained. No retry, replacement case or automatic continuation is allowed.

## Identity and authority

`verifiedEvidenceRefs` currently establishes reference resolution and matching
Task/Room, not source truth or permission to read. QA-071's existing Result
projection connects criteria, immutable sources and candidate verification;
it does not grant access to arbitrary original files. Historical QA-069 IDs
are excerpt IDs rather than Central object references. They require an
explicit mapping to owner-approved, version-pinned excerpt bytes.

The experiment authority binds experiment, Task, Room, Finalizer Run, evidence
identity, revision, digest and permitted byte range. The model cannot choose
paths, URLs, owner, Run or authority. A receives no read grant; B/C receive the
same per-source scopes, differing only in their invocation identity. Reuse
ordinary Results where structured Results exist. Original plain replies stay
plain replies; never invent historical criterionClaims or add contribution
persistence. No production scheduling, storage, participant selection,
completion, acceptance or permission policy changes.

## Receipts and assessment

A read receipt records runId, evidenceRef, revision, contentSha256,
requestedRange, returnedRange, returnedBytes, truncated, status,
failureReason and observedAt, plus the experiment authority pins. It records
what the reader returned, not what the model understood or verified.

Assess target-error correction, correct-content preservation, unsupported
additions, uncertainty preservation, required-deliverable coverage,
evidence-use compliance, source reads and Run outcome/time separately. Retain
item-level reasons and answer excerpts; do not calculate a net score.

Only sample-local explanations are permitted. A wrong/B wrong/C correct
supports an explicit-use signal in this case. A wrong/B correct/C correct
supports an access signal here. All wrong means these interventions failed;
inspect returns, compliance and relevance before attributing a cause. All
correct means the historical failure did not reproduce. Even stable C success
does not establish Discussion product quality. A fresh independent case would
require a new frozen plan and authorization.
